结局 · 每个分支给用户什么话
A
URL 格式不对 · 正则不匹配
不可重试 · 教格式
“That doesn't look like a GitHub repo URL. Send a link like github.com/owner/repo”
直接 reply_text —— 这一步还没建占位消息，不留一条空转的 ⏳ 挂在会话里
B
GitHub 403 → error: "rate_limit"
可重试 · 给时长
“GitHub API rate limited. Try again in a minute.”
明确「多久之后」再试 —— 不说“稍后重试”这种没有信息量的话
C
404 / 非 200 → "not_found" | "api_error"，或 fetch 返回 None
归因不确定
“Couldn't access that repo. It might be private or the URL might be wrong.”
私有仓和拼错 URL 在 API 层看不出区别 —— 就并列两种可能，让用户自己判断
fetch 返回 None 时复用 A 的那句文案（同一种「你给的链接有问题」）
D
Claude 分析抛异常 → 降级保存，不丢数据

basic_content: relevance_score: 0  ·  "Analysis failed — raw metadata only."

“Saved the link but analysis failed. You can try again with /repo <url>”
告诉用户「存住了什么」＋「怎么重来」，而不只是说失败了
